# ディベート支援アプリ 改修要件 v6（草案）

> v5（`REQUIREMENTS.md`）からの大幅改修。機能を絞り込み、「自分の立論を登録して質疑で鍛える」ことと
> 「AIが立論・資料一式を作る」ことの2本柱に再編する。
> 本書は質問による整理の途中経過であり、§9 の未決事項は引き続き確認する。
> 改訂: 第2回確認（情報源・数字の根拠・フローチャート方式・過去テーマ・本数上限・画面構成を確定）
> 改訂: 第3回確認（登録立論の数字検査・生成回数の数え方・生成中のテーマ変更・対象外情報源の扱いを確定）
> 改訂: 第4回確認（生成時の字数調整・確認済の操作・練習結果の活用を確定。未決事項なし）
> 改訂: 第5回確認（立論の削除機能を置かない／テキスト練習の講評を実装する範囲を確定）

---

## 0. 改修の方針

- 機能は §2 の一覧**だけ**に絞る。それ以外の v5 機能は削除する（§8）
- v5 の根本的な制約は変更しない（§1）。ただし「資料の完成」を求める新要件に合わせ、
  **捏造防止の制約の書き方だけを改める**（§1-3）

## 1. 引き継ぐ根本制約

| 9 | **数字には必ず根拠と妥当性を持たせる**（新設） | 下記 1-9 |

### 1-3 捏造防止（改訂）

v5 は「引用文・出典はAIに一切書かせない」だった。v6 では**実在を機械的に確かめられたものだけ**AIが埋める。

- 資料生成時に、§1-3a の情報源**だけ**から実在の情報を取得する
- **引用文は、取得したページ本文に実在する文字列のみ**。保存前にコード側で本文との一致を検査し、一致しなければ採用しない
- 出典には URL と**最終確認日**を必ず付ける（実物の参考資料の書式に合わせる）
- 法令の条文は e-Gov から取得する（LLM に書かせない）
- 取得できなかった資料は完成させず、「作成手順」を出す（§3.4）
- すべて「AI取得（未確認）」で保存し、人が確認して「確認済」に上げる

### 1-3a 取得してよい情報源

| 区分 | 情報源 | 用途 |
|------|--------|------|
| 官公庁 | 各府省庁・国税庁・財務省・総務省等の公式サイト、審議会資料 | 制度の趣旨・現状・政府見解 |
| 統計 | e-Stat（政府統計の総合窓口）、各府省の統計ページ | 統計資料 |
| 国会 | 国会会議録検索システム | 立法趣旨・答弁 |
| 法令 | e-Gov 法令検索 | 条文 |
| 判例 | 裁判所 裁判例検索 | 判例を資料（precedent）として使う場合 |
| 論文 | CiNii Research、J-STAGE（本文を取得できる公開PDFに限る） | 法解釈・制度趣旨・学説 |

- **新聞・民間調査・一般サイトは取得対象にしない**（ユーザーが自分で見つけて登録するのは可）
- 上記以外のドメインから取得したものは資料として採用しない（コード側でドメインを検査）

### 1-9 数字の根拠と妥当性（新設）

立論・資料・質疑回答・最終弁論の雛形に出てくる**すべての数字**に次の4点を課す。

| 観点 | 内容 | 満たさないとき |
|------|------|----------------|
| 出典の明記 | 統計名・表番号・調査年（年次）・単位・URL・最終確認日を付ける | **出典のない数字は立論にも資料にも入れない** |
| 計算の再現 | 割合・伸び率・差・一人当たり等は**コードで計算**し、元の数値 → 式 → 結果を資料に載せる | LLM が計算した数字は採用しない |
| 比較の前提 | 比べる数字同士の年次・定義・単位・対象範囲・名目／実質がそろっているかを検査 | そろわなければ警告し、そろえ直すか比較をやめる |
| 使い方の妥当性 | その数字が主張を本当に支えるか（相関と因果の混同、都合のよい年だけの切り取り、母数の違い、平均で隠れる分布など）を点検 | 突かれる恐れを**弱点**として §7 と質疑（§4）に反映する |

## 3. 立論と資料

### 3.1 立論の出どころ

| 区分 | 作り方 | 生成されるもの |
|------|--------|----------------|
| 登録（自作） | .docx / PDF の立論＋資料セットをアップロード | 質疑＋回答、フローチャート、最終弁論雛形、特徴と戦い方 |
| 生成（AI） | テーマから生成。各側1本から始め、1テーマにつき各側3本まで | 上記すべて＋立論本文＋資料 |

登録・生成を区別せず、同じ画面・同じ機能で扱う（出どころはラベルで示す）。

### 3.2 登録の取り込み

1. .docx／PDF から本文を抽出（スキャン画像だけのPDFは対象外と明示）
2. 立論を Ⅰ主張／Ⅱ理由（見出し・(1)(2)(3)）／Ⅲ結論 に構造化
3. 立論中の `【資料N参照】` と資料ファイル中の `【資料N】` を番号で対応付け
4. 対応が取れない番号（立論にあるが資料にない等）は取り込み結果画面で指摘する
5. 読み上げ時間の目安を表示（F10）
6. **数字の検査（§1-9）をかけて指摘する**。出典のない数字・比較の前提のずれ・使い方の危うさを一覧で示し、弱点として §4・§7 に反映する。**立論本文は書き換えない**
7. §1-3a 以外の情報源（新聞・民間調査等）の資料は**そのまま使う**が、「信頼性を突かれやすい資料」と注意表示し、弱点に挙げる

### 3.3 生成の流れ

```
[任意] 論題分析（関連法令・争点・評価基準）→ 確認したい人だけここで止めて修正
  ↓ 既定は止めずに続行
立論骨子 → 立論本文（字数・形式を遵守） → 資料（取得・作成・手順） → 数字の検査（§1-9） → 以降は §4〜§7 共通
```

- 分析の確認関門は**任意**（既定は一気に生成。チェックを入れた場合だけ分析で止まる）
- 追加生成では、既存の立論と評価基準の枠組み・構成を変える
- **字数の自動調整**: 立論本文の字数をコードで数え、4分30秒超〜5分00秒に収まらなければ、削る／補う調整を**2回まで自動で**行う。それでも外れたら警告付きで保存する（早口前提の字数にはしない）

### 3.4 資料の完成度

| 種類 | AIがやること | 完成しない場合 |
|------|--------------|----------------|
| 法令 | e-Gov から条文を取得して掲載 | — |
| 引用資料（官公庁文書・会議録・判例・論文） | §1-3a の情報源から取得し、本文に実在する箇所を引用＋出典・URL・最終確認日 | 何を証明する資料か／検索語／探す場所／見つけたら何を抜き出すか、の手順 |
| 統計資料 | 実在の統計値を取得 → コードで計算 → **表＋グラフ画像**＋**計算過程**（どの統計のどの数値をどう計算したか）＋**比較の前提の検査結果** | 必要な統計表の名前と入手先／取り出す数値／計算手順 |
| 書籍・新聞 | 取得対象外のため完成しない | 書名・該当しそうな章・図書館での探し方 |

統計資料の作成は、ゼミ生にとって最も難しい作業であるため、**積極的にAIで完成させる**対象とする。

### 3.5 過去テーマからの資料コピー

- 過去テーマの資料を選んで現テーマの立論にコピーできる（立論本文はコピーしない）
- コピー後は資料番号を再採番し、状態は「確認済」でも**「未確認」に戻す**（テーマが変わると使い方の妥当性が変わるため）
- 出典の最終確認日はコピー元のまま表示し、古い場合は再確認を促す

## 4. 質疑

### 4.1 生成方針

- 対象: 登録・生成の**全立論**。すべてに模範回答を付ける
- 視点: 同じデータを**両面**で見せる。相手側から見れば「攻める質疑」、立論側から見れば「受ける質疑と回答準備」
- 規模: 最初は立論の**各段落×攻撃点（前提／根拠＝資料／因果／効果／数字の使い方）を一通り突く30〜40問程度**。
  「この箇所をもっと」で箇所を指定して追加生成でき、既存と同趣旨の質問は除外する
- 形式: 単発の質問に加え、**質問を重ねて詰める連鎖**（質問→想定回答→次の質問→…→引き出したい結論）を含める
- §1-9 の「使い方の妥当性」で見つかった弱点は、必ず質疑に入れる

### 4.2 整理の軸

- **立論の箇所別**（(1)担税力、(2)公平…のどこを突くか）
- **優先度順**＋**8分セット**（全量とは別に、実際の8分で使う前提のおすすめの流れ）
- 8分セットに**担当者の割り振りは入れない**（チーム内で決める）

### 4.3 練習結果の反映（F11 → 質疑データ）

| 反映 | 内容 |
|------|------|
| 詰まった質問の記録 | 練習で答えに詰まった質問に印を付け、質疑一覧で優先度を上げる |
| 新しい質問の追加 | 練習中にAIが出した未登録の質問を、模範回答つきで質疑データに追加（既存と同趣旨なら追加しない） |
| 最終弁論につなげる | 練習の質疑結果から、最終弁論の雛形（§6）の空欄を埋めた例を出す |

### 4.4 練習後の講評

テキストでの練習記録から**判定できる観点だけ**で講評する。判定できない観点は講評に含めず、その旨を画面に明記する。

| 判定できる（講評する） | 判定できない（講評しない） |
|------------------------|----------------------------|
| 質問の狙いが明確か／逃げを許さず詰められたか／同じ質問の繰り返し | 相手の発言をさえぎったか（要項6） |
| 引き出した答えを自分の主張・最終弁論に結びつけられたか | 20秒以上の沈黙（要項12・活発度）。入力に要した時間は発話の沈黙と一致しないため |
| 自分の立論と矛盾しない回答か／墓穴を掘る譲歩をしていないか | 声の大きさ・聞き取りやすさ（要項9） |
| 質問に答えていない回答・逆質問（確認の質問は可）（要項7） | |
| 1回の発言の長さ（字数から読み上げ秒数を推定。8分の配分に照らす） | |
| **生成済みフローチャートとの照合**：どの連鎖を使い、引き出したい結論まで到達したか／想定外の回答にどう対応したか | |

- 形式は v5 を引き継ぐ（よかった点 → 直す点 → 具体的な言い換え例 → 総評）。指摘は該当発言を引用して示す

## 5. 質疑フローチャート

- 全立論に対して生成する
- **分岐図＋台本**
  - 分岐図: 質問 → 想定回答の分岐（認める／否定する／はぐらかす）→ 次の質問 → 引き出したい結論、を色分けして全体を見せる
  - 台本: 分岐図のノードを押すと、そこまでの経路を会話形式で読める
- **画面は操作型**: 拡大・縮小、連鎖ごとの折り畳み、ノードを押して台本表示
- **印刷・PDF は静的な図**: 連鎖ごとにページを分け、台本を図の下に付ける（F12）

---

## 6. 最終弁論の雛形

- 1分≒約320字
- **穴埋め式＋記入例**
  - 枠: 「質疑で相手は【○○】を認めた」のように、質疑の結果を差し込む欄
  - 記入例: フローチャートの主要な経路ごとに、埋めた後の完成例
- 主張の繰り返し・新論点にならない構成にする（要項10）
- 印刷して試合中に手書きで埋められる（F12）

---

## 7. 立論の特徴と戦い方

各立論に次の2点を付ける。

- **強みと弱点**: 柱になる論点、突かれやすい箇所（§1-9 で見つかった数字の弱点を含む）
- **この立論で戦うとき**: 質疑で守るところ・譲ってはいけないこと、最終弁論で何を勝ち筋にするか
