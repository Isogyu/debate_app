# 審査要項からの実装要件

大学対抗 税法ゼミディベート大会の審査要項から、アプリの仕様に直結する項目を抜き出したもの。
原文は要項そのものを参照すること。ここは「実装がどう対応しているか」の対応表。

## 時間（要項5）

> ディベートにあたっては、立論5分、質問8分、最終弁論1分で時間厳守とする。
> **時間オーバーや30秒以上時間が余った場合**は審査員の判断で減点することができる。
> タイムキーパーは、1分前と30秒前に合図をおこない、終了時に時間を読み上げる。
> なお、「終了時」とは、**立論に記載された最後の文字を読み上げた時点**とする。

| 要件 | 実装 |
|------|------|
| 立論の適正は **4分30秒超〜5分00秒** の30秒幅 | `src/domain/speech.ts` の `MIN_ACCEPTABLE_SECONDS`。判定は over / ok / **short** の3値 |
| 短すぎても減点 | 立論画面のメーターが「30秒以上余ります」と警告。生成の指示にも下限を入れている |
| 立論5分・質疑8分・最終弁論1分 | タイマーが3種目に対応（`SPEECH_KINDS`） |
| 1分前・30秒前の合図 | タイマーが本番と同じ合図を出す |
| 終了時＝最後の文字 | 文字数の数え方がこれに対応（資料の参照記法・罫線は読み上げないので数えない） |

## 分量の調整（要項11）

> 時間調整のため**早口だったり、遅すぎる口調**だったりする場合は、立論のボリュームに関する
> アイデアが足りないものとして、審査員の判断により減点することができる。

→ 速度で帳尻を合わせるのは不可。**文字数そのものを適正にする**。
生成の指示に「読む速さで帳尻を合わせるのは不可」と明記している。

この条項があるため、**読み上げ支援に音声認識は使わない**。誤認識で位置が
ずれたまま「巻いてください」と指示すれば早口になり、この条項で減点される。
支援が減点の原因になっては本末転倒。代わりに経過時間から目安位置を示す
ペースメーカー（`src/domain/pacing.ts`）を置いている。

## 質疑のマナー（要項6・7・12）

| 減点項目 | 実装 |
|----------|------|
| 相手の発言を頻繁にさえぎる | シミュレーターの講評観点に含めた |
| 相手の質問に意図的に答えない | 同上。AI側にも「聞かれたことに答える」と指示 |
| 相手の質問時間の**逆質問**（確認の質問は可） | 同上。AI側にも禁止を指示 |
| 20秒程度以上の長い沈黙（活発度） | 講評観点に含めた |

## まだ実装していない要件

| 要項 | 内容 | 対応案 |
|------|------|--------|
| 4 | **事前の合意事項**を双方でまとめ試合前に提出。違反すると減点 | 論題ごとに合意事項を記録する場所が要る |
| 8 | **連携力**。質問や回答が特定の人に偏ると減点 | 誰がどの質疑を担当するかの割り振り表 |
| 9 | 立論は**プレゼンテーション**として審査（声の大きさ・聞き取りやすさ） | アプリで支援しにくい。練習時の注意として出すくらい |
| 10 | **最終弁論**は質疑を踏まえること。主張の繰り返しや新論点は減点 | 最終弁論の組み立て支援（質疑の記録から材料を拾う） |
| 採点 | 各項目3点標準・0〜5点 | A2ルーブリックの設計に使う |

## 実装しないと判断した要件

### 要項3（素材とする判決）

> 素材とする判決の事実関係、判決の内容を適切に踏まえているか。理解が不正確な場合、
> 判決の内容に触れていない場合には、**減点とすることができる**。

当初これを最優先と評価したが、**誤りだった**。

- 条文は「減点とすることが**できる**」という審査員の裁量規定であり、義務ではない
- 実際の運用では、判決に一切触れずに戦って減点されなかった実績がある（本ゼミの経験）
- 手元の実物の立論4件も、特定の判決には触れず学説と統計で構成されている
- 要項13に「**判例ディベート**における立場は…」とあり、要項3は判例ディベート向けの
  条項と読める。本ゼミが取り組むのは政策ディベートで、構成は比較的自由

したがって「素材判決」をデータモデルに持たせ、生成のたびに必ず踏まえさせる、
という実装はしない。**判決を使いたい場合は、資料（`sourceType: "precedent"`）として
登録すれば足りる**。裁判所の裁判例検索も情報源に入れてある。
