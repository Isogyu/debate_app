# 画面設計書（ワイヤーフレーム・要素定義）

> REQUIREMENTS.md と対になる画面設計書。
> 対象ユーザーは非情報系のため、**専門用語には必ず注釈(?)アイコン**、**主要操作は3クリック以内**、**本番モードは2タップで「返し」に到達**を徹底する。
>
> v2: `REVIEW.md` の指摘を反映（本番モードの到達段数の定義明確化・性能目標の数値化・アクセシビリティ要件の追加）

## 0. 共通レイアウト

### グローバルナビゲーション（準備フェーズ）

```
┌──────────────────────────────────────────────────────────────┐
│ ディベート支援          [ホーム] [練習問題] [ガイド] [管理]      │
└──────────────────────────────────────────────────────────────┘
```

- ヘッダーは常時表示。アプリ名は平易な表記（内部名「ディベート支援」で可）
- パンくず: `ホーム > [論題名] > 立論` のように現在位置を明示
- (?)アイコン or 下線付き用語にホバー/タップで用語解説ポップアップ

### 本番モードは別レイアウト

- グローバルナビ非表示、画面いっぱいをコンテンツに使用
- 「終了（準備画面へ戻る）」ボタンのみ小さく配置
- 誤って編集できないよう読み取り専用

## 1. プロジェクト一覧（HOME）

**目的**: 論題ごとの成果物にアクセスする起点

```
┌──────────────────────────────────────────────────────────┐
│ ディベート支援                          [ガイド] [管理]    │
├──────────────────────────────────────────────────────────┤
│                                                          │
│  [＋ 新しい論題で準備を始める]      [本番モード]            │
│   ――――――――――――――――――――――――――――――――――――――――――――――――    │
│                                                          │
│  あなたのプロジェクト                        🔍 検索       │
│ ┌─────────────────────┐ ┌─────────────────────┐          │
│ │ 所得税法56・57条廃止 │ │ 論題タイトル...      │          │
│ │ [肯定側] 完成✓       │ │ [否定側] 生成中…    │          │
│ │ 更新: 2026/09/18    │ │ 更新: 2026/09/15    │          │
│ └─────────────────────┘ └─────────────────────┘          │
└──────────────────────────────────────────────────────────┘
```

| 要素 | 仕様 |
|------|------|
| 新規作成ボタン | 画面最大・最上部。アプリを開いて最初に目に入る |
| 本番モードボタン | 会場で開いたとき即座に使えるよう新規作成と同格で配置 |
| プロジェクトカード | 論題・立場バッジ（肯定=緑/否定=橙）・ステータス（分析中/生成中/完成）・更新日 |
| ステータス | 「完成」以外は進捗率を表示（例: 生成中 5/8） |

## 2. 論題入力ウィザード（WIZ）

**目的**: 論題と立場を入力して分析を開始

```
┌──────────────────────────────────────────────────────────┐
│ 新しいプロジェクト         ①論題入力 ─ ②分析確認 ─ ③生成  │
├──────────────────────────────────────────────────────────┤
│                                                          │
│  論題を入力してください                                    │
│  ┌────────────────────────────────────────────────────┐ │
│  │ 例: 日本は所得税法第56条および第57条を廃止すべきである│ │
│  └────────────────────────────────────────────────────┘ │
│  ※「〜すべきである」の形で書くと分析しやすくなります       │
│                                                          │
│  あなたの立場は？ (?)                                     │
│  ┌──────────────┐  ┌──────────────┐                     │
│  │  肯定側       │  │  否定側       │                     │
│  │ 実施すべきと  │  │ 実施すべきで  │                     │
│  │ 主張する側    │  │ ないと主張する│                     │
│  └──────────────┘  └──────────────┘                     │
│                                                          │
│  チーム名・メンバー（任意・Word出力の表紙に使います）        │
│  チーム名 [________]  メンバー [____________________]     │
│                                                          │
│                                    [論題を分析する →]    │
└──────────────────────────────────────────────────────────┘
```

| 要素 | 仕様 |
|------|------|
| 論題入力 | 複数行テキスト、プレースホルダーに実例 |
| 立場選択 | 大きな選択カード。用語注釈付き |
| チーム情報 | 任意入力。エクスポートのヘッダーに使用 |
| 分析ボタン | 押下後ローディング→分析確認画面へ遷移 |

## 3. 分析確認画面（ANAL）

**目的**: AIの分析結果を**必ず人間が確認・修正**してから生成に進む（品質ゲート）

```
┌──────────────────────────────────────────────────────────┐
│ 分析結果の確認              ①論題入力 ─ ●分析確認 ─ ③生成 │
├──────────────────────────────────────────────────────────┤
│ ⚠ AIの分析です。間違いがあればこの画面で直してください      │
│                                                          │
│ ■ この政策が変えるもの (?)                                │
│ ┌────────────────────────────────────────────────────┐ │
│ │ 所得税法56・57条（親族への対価の必要経費不算入・特例）│ │
│ └────────────────────────────────────────────────────┘ │
│                                                          │
│ ■ 関連する法令 (?)                          [＋追加]      │
│ ┌────────────────────────────────────────────────────┐ │
│ │ ・所得税法 第56条 [編集] [×]                        │ │
│ │ ・所得税法 第57条 [編集] [×]                        │ │
│ │ ・日本国憲法 第14条 [編集] [×]                      │ │
│ └────────────────────────────────────────────────────┘ │
│                                                          │
│ ■ 争点カテゴリ (?)                          [＋追加]      │
│ [担税力] [公平性] [中立性] [簡素性] [所得分散防止] [税務DX]│
│                                                          │
│ ■ 評価基準の枠組み (?)                                    │
│ ┌─肯定側──────────────────────┐ ┌─否定側───────────────┐│
│ │租税公平主義                  │ │税の基本原則(税制改革法3││
│ │[担税力][公平][中立性]        │ │条) [公平][中立][簡素] ││
│ │[編集]                        │ │[編集]                 ││
│ └─────────────────────────────┘ └──────────────────────┘│
│                                                          │
│                    [← 戻る]        [この内容で生成開始 →]  │
└──────────────────────────────────────────────────────────┘
```

| 要素 | 仕様 |
|------|------|
| 警告バー | AI生成であることを明示し、確認を促す（品質ゲート） |
| 関連法令 | 条文はここでは一覧のみ。全文は資料画面で確認 |
| 争点カテゴリ | チップ形式で追加・削除。**全成果物の検索軸になる** |
| 評価基準枠組み | 両側それぞれ独立して編集可能（実物でも両側で異なる枠組み） |
| 生成開始 | 押下→進捗モーダル→ダッシュボードへ |

**生成進捗モーダル**
```
┌──────────────────────────────┐
│ 生成しています…               │
│ ✓ 立論（肯定側）              │
│ ✓ 立論（否定側）              │
│ ⏳ 資料要件リスト… 3/8        │
│ ○ 質疑フローチャート           │
│ ○ 反駁シート                  │
│ ○ ブロック集                  │
│ ○ 比較衡量                    │
│ ※数分かかります。閉じてもOK   │
└──────────────────────────────┘
```

| 要素 | 仕様 |
|------|------|
| 進捗の実体 | `GenerationJob.steps`（8ステップ）をポーリングして表示。**サーバー側のジョブとして動くため、ブラウザを閉じても生成は続く** |
| 失敗時 | 失敗したステップのみ「✗ 資料要件リスト — 生成できませんでした [このステップだけ再実行]」と表示。他のステップは止めない |
| エラー文言 | 日本語で「何が起きたか」「次に何をすればよいか」。HTTPステータスやスタックトレースは見せない |
| 離脱導線 | 「閉じてもOK」は文言だけでなく、閉じた後もダッシュボードに進捗バーを出し続ける |

## 5. 立論画面（CASE）

**目的**: 実フォーマット（Ⅰ/Ⅱ/Ⅲ）の立論を閲覧・編集・部分再生成

```
┌──────────────────────────────────────────────────────────┐
│ ホーム > [論題] > 立論                                    │
├──────────────────────────────────────────────────────────┤
│ [肯定側] [否定側]        表示: [構造表示|Wordプレビュー]   │
│                                                          │
│ Ⅰ. 主張                                         [編集]   │
│ ┌────────────────────────────────────────────────────┐ │
│ │ 所得税法56条および57条を廃止するべきである。          │ │
│ └────────────────────────────────────────────────────┘ │
│                                                          │
│ Ⅱ. 理由                                                   │
│ 1. 問題点（租税公平主義の観点から）               [編集]   │
│   ┌─（1）担税力に即した課税 ─────────[担税力][公平性]──┐ │
│   │ 純資産増加説を採用するわが国では…【法37条】[資料2]  │ │
│   │ …担税力に即した課税に反する規定といえる[資料3]。    │ │
│   │                          [編集] [この部分を再生成] │ │
│   └──────────────────────────────────────────────────┘ │
│   ┌─（2）公平 ─────────────────────[公平性]──────────┐ │
│   │ …                                                │ │
│   └──────────────────────────────────────────────────┘ │
│   ┌─（3）中立性 ────────────────────[中立性]─────────┐ │
│   │ …                                                │ │
│   └──────────────────────────────────────────────────┘ │
│ 2. 廃止する環境                                   [編集]  │
│   ┌──────────────────────────────────────────────────┐ │
│   │ 2009年以来政府は「検討する」姿勢を…[資料7]         │ │
│   └──────────────────────────────────────────────────┘ │
│                                                          │
│ Ⅲ. 結論                                         [編集]   │
│ ┌────────────────────────────────────────────────────┐ │
│ │ 以上より、所得税法56条および57条を廃止するべきである。│ │
│ └────────────────────────────────────────────────────┘ │
└──────────────────────────────────────────────────────────┘
```

| 要素 | 仕様 |
|------|------|
| 側タブ | 肯定/否定を切替。実フォーマットのⅠ/Ⅱ/Ⅲ構造を再現表示 |
| パターン切替 | 同一論題の複数立論バリエーションがある場合、上部に「パターン ▼」で切替。採用立論/相手想定パターンのバッジ表示 |
| Claimカード | （1）（2）（3）のサブセクション=カード。右上にカテゴリタグ |
| 資料リンク | `[資料N]` `【法N条】`はクリッカブル→資料要件画面の該当箇所へ |
| 部分再生成 | カード単位・段落単位で再生成（全体を壊さない） |
| Wordプレビュー | エクスポート時の見た目を確認できる切替 |

## 6. 資料要件画面（SRC）

**目的**: 「どんな資料が必要か」→「実際に見つけて登録する」までを管理

```
┌──────────────────────────────────────────────────────────┐
│ ホーム > [論題] > 資料要件                                │
├──────────────────────────────────────────────────────────┤
│ 絞り込み: [全て][担税力][公平性][中立性]…   状態: [未発見▼]│
│                                                          │
│ ┌──────────────────────────────────────────────────────┐│
│ │ 資料1  租税公平主義の定義          [学術書] [担税力]    ││
│ │ 証明すること: 税負担は担税力に即して公平に配分されるべき││
│ │ という原則があること                                  ││
│ │ 探し方: 「租税公平主義」「担税力」→ 専門書・租税法教科書││
│ │ 情報源: [CiNii] [国会図書館]                          ││
│ │ 使用箇所: 肯定側立論（1）担税力 にリンク               ││
│ │ 状態: ●発見済                                        ││
│ │ 出典: 金子宏『租税法〔第24版〕』（弘文堂・2021年）88頁  ││
│ │ [出典を編集] [引用文を登録]                           ││
│ └──────────────────────────────────────────────────────┘│
│ ┌──────────────────────────────────────────────────────┐│
│ │ 資料7  廃止に対する政府見解        [国会] [時代遅れ]    ││
│ │ 証明すること: 政府が廃止を「検討する」としつつ環境が   ││
│ │ 整っていないと主張してきたこと                        ││
│ │ 探し方: 「所得税法56条 廃止 答弁」→ 国会議事録・答弁書││
│ │ 情報源: [国会議事録検索] [衆議院質問主意書]           ││
│ │ 状態: ○未発見 → [出典・引用文を登録する]              ││
│ └──────────────────────────────────────────────────────┘│
└──────────────────────────────────────────────────────────┘
```

| 要素 | 仕様 |
|------|------|
| 資料番号 | 立論の【資料N参照】と対応。ソートは番号順 |
| 命題表示 | 「証明すること」を必ず明示（実物でタイトル=命題だったため） |
| 探し方 | 検索キーワード＋情報源への直リンク（e-Gov/議事録/e-Stat/CiNii等） |
| 状態 | 未発見/発見済/確認済の3段階。登録フォームで出典・引用文を記入 |
| 使用箇所 | どのClaimを支えるか逆リンク |
| ディベーター作成 | `self_made`種別の資料は「自分で作る資料」として計算補助（U20）へ導線 |

## 7. 質疑フロー画面（CX）

**目的**: 想定回答ごとの分岐を辿り、質疑を練習・準備する

```
┌──────────────────────────────────────────────────────────┐
│ ホーム > [論題] > 質疑フロー                              │
├──────────────────────────────────────────────────────────┤
│ 対象: [相手(否定側)の立論 ▼]   表示: [ツリー] [練習モード] │
│                                                          │
│ ┌─フローチャート表示─────────────┐ ┌─ノード詳細─────────┐│
│ │                                │ │ Q: なぜ親族への適正 ││
│ │  [Q1: 所得分散は本当に          │ │   対価を経費にしない││
│ │   防げるのか？]                │ │   のか？            ││
│ │    ├─[防げる]──→ [Q2: ではなぜ │ │                    ││
│ │    │            専従者給与は減少│ │ 意図: 制度目的の    ││
│ │    │            している？]    │ │ 前提を揺さぶる      ││
│ │    └─[防げない]→ [Q3: 防げない │ │                    ││
│ │                  なら一律制限は│ │ 狙い: 「生計を一に」 ││
│ │                  過剰では？]   │ │ 要件の限定性を認めさ││
│ │                                │ │ せる               ││
│ └────────────────────────────────┘ └────────────────────┘│
└──────────────────────────────────────────────────────────┘
```

| 要素 | 仕様 |
|------|------|
| ツリー | Mermaid/React Flowで分岐描画。ノード=質問、枝=想定回答 |
| ノード詳細 | クリックで右パネルに質問文・意図・各回答後の展開 |
| 練習モード | 想定回答をクリックして分岐を実際に辿る（本番の流れを体感） |
| 対象切替 | 相手側立論を攻める質疑 / 自分が受ける質疑の両方を生成可能 |

## 8. 反駁・比較画面（REB）

```
┌──────────────────────────────────────────────────────────┐
│ ホーム > [論題] > 反駁・比較                              │
├──────────────────────────────────────────────────────────┤
│ ■ 相手（否定側）の主張への反駁                            │
│ 相手の主張: [（1）公平 — 恣意的所得分散の防止に資する ▼]   │
│ ┌──────────────────────────────────────────────────────┐│
│ │ 攻撃ポイント: [前提][根拠][因果][効果]  ←タブ切替      ││
│ │ ┌──────────────────────────────────────────────────┐ ││
│ │ │ [因果] 「所得分散を防ぐ→公平になる」の因果が弱い。  │ ││
│ │ │ 一律制限は適正対価の支払いも巻き込み、むしろ異なる  │ ││
│ │ │ 状況を同じ扱いにして不公平を生む。【資料4参照】     │ ││
│ │ │                                    [ブロックに追加]│ ││
│ │ └──────────────────────────────────────────────────┘ ││
│ └──────────────────────────────────────────────────────┘│
│                                                          │
│ ■ 比較衡量                                               │
│ ┌──────────┬────────────────┬────────────────┐          │
│ │ 評価基準  │ 廃止する(肯定)  │ 維持する(否定)  │          │
│ ├──────────┼────────────────┼────────────────┤          │
│ │ 公平      │ 適正対価も認める│ 所得分散を防ぐ  │          │
│ │ 中立      │ 選択の歪み解消  │ 偏向に歯止め    │          │
│ │ 簡素      │ 複雑化する      │ 事務負担が軽い  │          │
│ └──────────┴────────────────┴────────────────┘          │
│ 判断の軸: 現代の環境変化(DX・記帳義務化)を踏まえると…      │
└──────────────────────────────────────────────────────────┘
```

| 要素 | 仕様 |
|------|------|
| 攻撃点タブ | 前提/根拠/因果/効果の4分類（データモデルのattackPointに対応） |
| ブロック追加 | 反駁をワンクリックでブロック集（本番用）に送る |
| 比較衡量表 | 評価基準×両側の対比表＋判断の軸（verdictLogic） |

## 9. ブロック集画面（BLK）

**目的**: 「相手がXと言ったら→Yを返す」をカテゴリ別に整理（本番の武器）

```
┌──────────────────────────────────────────────────────────┐
```

## 10. 本番モード（LIVE）★最重要

**目的**: 本番中に**2タップで「返し」が読める**。PCメイン・スマホ可

**到達段数の定義（重要）**

| タップ数 | 到達するもの |
|----------|--------------|
| 1タップ目 | 争点カテゴリを選ぶ |
| **2タップ目** | **ブロック一覧。カードに「相手の主張」と「返しの要点」を表示済み → 実用上ここで完結する** |
| 3タップ目 | 詳細（使える資料・質疑・関連する反駁） |

## 14. 設計上の一貫ルール

| ルール | 内容 |
|--------|------|
| カテゴリ軸 | 争点カテゴリが全成果物・検索・本番モード・ブロック集の共通軸 |
| 相互リンク | 立論↔資料番号、反駁→ブロック、質疑→ブロックはすべて双方向リンク |
| 用語注釈 | 担税力・中立性・比較衡量・コンテンション等は(?)で解説表示 |
| 待たせない | 生成は必ず進捗表示＋途中離脱OK。検索・本番モードは即応答 |
| 壊さない編集 | 部分再生成はカード/段落単位。全体を巻き込まない |
| 本番専用UI | 本番モードは別レイアウト・読取専用・2タップで返し到達・オフライン対応 |
| AI生成の明示 | 生成物には「AI生成（未確認）／人が確認済み」のバッジを常時表示する。エクスポート成果物にも同じ表示を残し、確認前の内容を確認済みに見せない（REQUIREMENTS §6.2 信頼性） |
| 資料番号の整合 | 立論本文の【資料N参照】と参考資料の番号は常に一致させる。パターン切替・資料増減時は再採番して両方を同時更新する |
| アクセシビリティ | 本番モードは本文16px以上・タップ領域44px以上・コントラスト比4.5:1以上 |
