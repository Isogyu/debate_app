# デプロイ手順（Fly.io）

ゼミ生が各自のPC・スマホから使えるようにするまでの手順。
URLを1つ配るだけで済む形にする。

## なぜFly.ioか

- SQLiteを**そのまま**使える（永続ボリュームが付けられる）
- 生成ジョブを**バックグラウンドで数分走らせられる**（サーバーレスだと途中で止まる）
- HTTPSが自動で付く（オフライン対応＝PWAの必須条件）
- 管理者PCの電源に依存しない

> Vercelは使えない。ファイルシステムが永続せずSQLiteが消え、
> 関数がレスポンス後に終了するため8ステップの生成が完走しない。

## 1. 初回のデプロイ

```bash
brew install flyctl
fly auth login
fly launch --no-deploy   # fly.toml があるので設定はそれを使う
fly volumes create debate_data --region nrt --size 1
```

## 2. 秘密情報を設定する

```bash
fly secrets set ANTHROPIC_API_KEY=sk-ant-... DEBATE_APP_PASSWORD=ゼミの合言葉
```

`fly secrets` はイメージに焼き込まれず、リポジトリにも残らない。

## 3. デプロイ

```bash
fly deploy
fly open        # 発行されたURLが開く
```

URL（`https://debate-app.fly.dev` 等）をゼミ生に配る。配るのはこれだけ。

## 4. ゼミ生側の初回設定（1回だけ）

電波のある場所で以下をやってもらう。

1. 配られたURLを開く
2. 合言葉と名前を入れてログイン
3. **ホーム画面に追加する**
   - iPhone: Safariの共有ボタン → 「ホーム画面に追加」
   - Android: Chromeのメニュー → 「ホーム画面に追加」
4. 使う論題の「立論」「資料要件」「ブロック集」「質疑フロー」「本番モード」を一度ずつ開く

これで、**電波がなくてもホーム画面のアイコンから起動して閲覧・質疑練習ができる**。

## 5. 練習・模擬戦の当日

- 電波の有無に関わらず、ホーム画面のアイコンから起動する
- オフライン時は画面上部に赤い帯が出て、編集・生成のボタンが押せなくなる
- 内容を更新したら、ゼミ生には電波のある場所で一度開き直してもらう

## 運用の注意

| 項目 | 内容 |
|------|------|
| マシンは1台のまま | SQLiteなので増やすとデータが分かれる。`fly scale count 1` を維持する |
| バックアップ | `fly ssh console -C "ls /app/data/backups"`。マイグレーション時に自動取得される |
| 手元に落とす | `fly ssh sftp get /app/data/debate.db ./debate.db` |
| 合言葉の変更 | `fly secrets set DEBATE_APP_PASSWORD=新しい合言葉`。全員のログインが切れる |
| コストの確認 | 管理画面（`/admin`）でAPI使用量を見る。一般ユーザーには出ない |

## 紙の併用を勧める

サーバーもスマホも当日に壊れることがある。
エクスポート画面から**ブロック集を印刷**して持っておくのが最終手段になる。
