# ディベート支援アプリ（debate_app）

政策ディベートの**準備〜本番**を支援するWebアプリ。
論題を入力すると、肯定側・否定側の立論・資料要件・質疑・反駁・ブロック集を
一貫した論証構造として生成し、本番では争点カテゴリから2タップで「返し」を引ける。

設計ドキュメントは [`docs/`](docs/) にある。

| ドキュメント | 内容 |
|--------------|------|
| [docs/REQUIREMENTS.md](docs/REQUIREMENTS.md) | 要件定義・データモデル・生成パイプライン（v4） |
| [docs/DESIGN.md](docs/DESIGN.md) | 画面設計・ワイヤーフレーム |
| [docs/REVIEW.md](docs/REVIEW.md) | v3に対する多角的レビューと修正方針 |
| [docs/JUDGING.md](docs/JUDGING.md) | 審査要項から抜き出した実装要件と対応状況 |

## セットアップ

```bash
npm install
cp .env.example .env
npm run db:migrate
npm run dev
```

`.env` に最低2つ設定する。

| 変数 | 内容 |
|------|------|
| `ANTHROPIC_API_KEY` | Claude APIキー。**これがないと生成機能が一切動かない** |
| `DEBATE_APP_PASSWORD` | ゼミで共有する合言葉。これを知っている人だけがログインできる |

APIキーはサーバー側だけで使う。`NEXT_PUBLIC_` を付けるとブラウザに露出するので付けないこと。
合言葉が未設定だと誰もログインできない（誤って公開状態になるのを防ぐため、そういう挙動にしてある）。

### 使い方

1. 各自が自分のPC・スマホからサーバーのURLを開く
2. 合言葉と名前を入れてログイン（名前は「誰が直したか」の記録用）
3. 論題を入力 → AIの分析を確認・修正 → 生成 → 立論・資料要件・質疑・反駁・ブロック集ができる

### Docker で動かす

```bash
docker compose up -d
```

`./data` をボリュームマウントしている。**これを外すとコンテナを作り直した瞬間にデータが消える。**

### ゼミで使う（Fly.io）

手順は [docs/DEPLOY.md](docs/DEPLOY.md)。配るのは**URL 1つだけ**で、
ゼミ生は初回に「ホーム画面に追加」すれば、以後オフラインでも閲覧と質疑練習ができる。

**Vercelには乗らない。** ファイルシステムが永続せずSQLiteが消え、
レスポンス後に関数が終了するため数分かかる生成が完走しない。

## 構成

```
src/
  domain/          ドメイン層（フレームワーク非依存）
    types.ts           データモデル（REQUIREMENTS §7）
    invariants.ts      不変条件。資料番号の再採番・循環検出・引用ルール
    schemas.ts         LLM構造化出力のZodスキーマ
    source-whitelist.ts 情報源ホワイトリスト（捏造防止）
    case-format.ts     立論の整形と【資料N参照】の解析（純粋関数）
  db/              永続化（Drizzle + SQLite/WAL）
  lib/
    llm/             LLM抽象化レイヤ（差し替え可能）＋プロンプト
    jobs/            生成ジョブのランナーと8ステップ
    export/          Word生成とエクスポート用データの組み立て
  app/             画面・APIルート
  components/
tests/             不変条件のテスト
docs/              設計ドキュメント一式
```

## 設計上、特に注意すべき点

実装を引き継ぐ人が最初に踏みやすい落とし穴。詳細は
[docs/REVIEW.md](docs/REVIEW.md) を参照。

### 1. 資料番号は「立論パターンごと」にスコープされる

`【資料N参照】` の N はプロジェクト全体で一意ではない。
同一論題に複数の立論パターンがあり、それぞれ必要な資料が違うため、
**番号は `CaseVariant` の中で 1..N**、資料の実体（`SourceMaterial`）は
プロジェクト内で共有される。

立論を編集したら必ず `validateVariant()` を通すこと。
資料番号を登場順に振り直し、本文中の `【資料N参照】` も同時に書き換える。
ここを飛ばすと、立論と参考資料の番号がずれてエクスポートが使い物にならなくなる。

### 2. 生成はHTTPリクエスト内で完結させない

生成は数分かかり、「ブラウザを閉じてもOK」が要件。
`GenerationJob` をDBに作り、バックグラウンドで8ステップを進め、
クライアントは `/api/jobs/:id` をポーリングする。
ステップ単位で状態を保存しているので、途中で失敗しても
**失敗したステップだけ再実行**できる。

### 3. 実際に回して分かったこと（重要）

練習用の論題で全8ステップを通した結果、**プロンプトの指示だけでは守られない**
ことが複数見つかった。同じ轍を踏まないよう、コード側の防御をテストで固めてある
（`tests/generation-guards.test.ts`）。

| 症状 | 原因 | 対処 |
|------|------|------|
| 質疑・反駁の生成が失敗し続ける | 出力が上限に達して切れ、JSONが壊れる | 既定上限を12000に引き上げ、`stop_reason` で切断を検出して専用エラーにした。同じ条件での再試行はしない（課金の無駄） |
| 「AI出力が読み取れません」としか出ず原因が追えない | 例外の詳細を捨てていた | 原因と生出力の先頭をサーバーログに残す |
| 分岐の終端で毎回失敗 | LLMは「値なし」を省略ではなく `null` で返す | 任意の文字列項目は `null` も受けて `undefined` に寄せる（`optionalText`） |
| 見出しが「1. Ⅱ-1. …」と二重採番 | LLMが見出しに番号を書く | `stripLeadingNumber()` で落とす。採番は表示側の責任 |
| 本文に【資料N参照】が1つもない | 宣言だけして本文に書かない | `ensureRefMarkers()` で文末に補う |
| 【資料s2参照】【資料2参照】と二重表示 | slot名が数字を含むと置換の正規表現に当たらない | 正規表現を修正 |
| ブロックの争点カテゴリが全件空 | カテゴリ一覧を渡していないので勝手な名前を作る | 一覧をプロンプトに添え、表記ゆれを正規化。それでも空なら束ねた反駁から引き継ぐ |
| 「受ける質疑」が0件 | `defense` で頼んでもLLMが `attack` と自己申告する | 依頼した向きを呼び出し側で強制する |
| 完了したはずのステップが未実行で done | 同じジョブを並行実行して状態を上書き | ステータスの条件付き更新で二重起動を防ぐ |

### 4. AIに書かせないもの

- **引用文・出典** — 存在しない出典の捏造になる。資料要件（何を証明すべきか・どう探すか）だけ生成する
- **法令の条文全文** — e-Gov等から取得し、`LawRef.verified` を立てる
- **情報源** — `source-whitelist.ts` のIDから選ばせる。範囲外は `sanitizeSuggestedSourceIds()` が落とす

### 5. 本番モードは別物として扱う

読み取り専用・グローバルナビなし・LLM不呼出。
検索対象は事前計算済みの `BlockEntry.searchText`、データは一度に
クライアントへ渡しきり、試合中にサーバーへ往復しない。
目標は画面遷移100ms・検索200ms。

### 6. 生成は分析でいったん止まる

8ステップのうち `analysis` だけを先に走らせ、**人が分析確認画面で承認するまで
残り7ステップを流さない**（`runJob(jobId, { only: ["analysis"] })`）。
LLMの法解釈は誤りうるので、間違った分析のまま立論まで作ってしまわないための関門。
承認時は `runJob(jobId)` を呼ぶだけでよい（済んだステップは自動で飛ばされる）。

### 7. Service Workerはページを壊してはいけない

`public/sw.js` の `respondWith` に失敗したPromiseを渡すと、サーバーが正常に
200を返していてもブラウザ側は **ERR_FAILED** になる。実際にCSSが読めず画面が
崩れた（環境要因の可能性もあり原因は確定していないが、起こりうる形だった）。
しかもゼミ生にはサイトデータの削除でしか直せない。

そのため `serveStatic` / `serveNavigation` は**すべての分岐でResponseを返す**。
キャッシュの読み書きが失敗しても握りつぶし、最後は素通しに戻る。
迷ったら素通し、が原則。

### 8. オフラインは「閲覧＋質疑練習」だけ

大学Wi-Fi・テザリング・電波なし、のどれでも練習できる必要がある。
Service Worker（`public/sw.js`）が閲覧系のページと静的資産を端末に残し、
一度オンラインで開けば以後オフラインでも起動する。

オフライン判定に `navigator.onLine` だけを使ってはいけない。
**大学Wi-Fiに繋がっているがサーバーへ届かない**状況がこの運用では最も多く、
そのとき編集ボタンが押せると黙って保存に失敗する。
`useOnline()` は `/api/health` を実際に叩いて到達性を確かめている。

### 9. PDFはサーバーで作らない

PDFは印刷ビュー（`/projects/[id]/print/[kind]`）＋印刷CSSで、
ブラウザの「PDFに保存」を使う。Puppeteerを入れるとDockerイメージに
Chromiumが乗って約400MB増えるうえ、コンテナに日本語フォント
（fonts-noto-cjk等）を入れ忘れると**文字が全部豆腐になる**。
印刷CSSならフォントはOS任せで、ゼミ生のどのPCでも同じ結果になる。
「管理者のPC1台で動く」構成（§6.1）との釣り合いでこちらを選んでいる。

Wordは `docx` ライブラリで実体のある .docx を返す。
こちらは書式の再現が要件（§12）なので、印刷では代替できない。

### 10. 立論は5分。分量が品質

**読み上げ5分を超えても、30秒以上余らせても減点される**（審査要項5）。
適正は **4分30秒超〜5分00秒** の30秒幅しかない。上限だけ見ていると
「余りすぎ」の減点を見逃す。実際、当初は超過だけを警告しており、
短い立論を「問題なし」と表示していた。

速度で帳尻を合わせるのも不可。早口・遅すぎは「立論のボリュームに関する
アイデアが足りない」として減点される（審査要項11）ので、**文字数そのものを
適正にする**しかない。

基準は実物から取った（`docs/samples/`）。実際の試合で使われた立論は本文
1,528字と1,577字で、逆算した読み上げ速度が320字/分、持ち分が1,600字。
`src/domain/speech.ts` がこの計算を持ち、テストは**実物のサンプルを読み込んで
「5分に収まる」と判定されることを確認している**。基準がずれたら気づける。

生成側は骨子の段階で小見出しを4〜6個に制限し、本文生成では1段落あたりの
字数目安を渡す。全体の字数だけ言っても守られない。
画面ではメーターを常時表示し、エクスポートと印刷でも警告する。

### 11. 品質向上はfew-shotで行う（FTしない）

`src/domain/exemplars.ts` に実際の試合で使われた立論2件を埋め込み、
生成時に「同じ側のお手本」を提示している。生成物ではなく本物である点に価値がある。

内容は真似させない。お手本は別の論題のものなので、論点まで引きずると的外れになる。
真似させるのは**構成・一文の密度・分量**の3つだけだとプロンプトで明示している。

ファインチューニングは選ばない。Claude APIが非対応であることに加え、スタイル転移には
数百件の学習データが要るのに実物は2件しかなく、自己生成データで学習させても
上限が元のモデルの品質になるため。

### 12. AIの失敗をそのまま見せない

SDKの例外は `401 {"type":"error",...}` のようなJSONの生文字列を message に持つ。
これをそのまま画面に出すと、ゼミ生には何が起きたか分からない。
`translateApiError()` で日本語に置き換えている（認証・混雑・サーバー側障害を区別）。
401/403 は何度やり直しても同じなので `LlmConfigError` にしてリトライを止める。

### 13. AI生成物であることを隠さない

生成直後は `Revision.origin = "ai"` の未検証状態。
画面にもエクスポートにも「AI生成（未確認）／確認済」を必ず表示する。
LLMの法解釈は誤りうるので、人のレビューを挟む前提で作る。

## 残っている論点

[docs/REQUIREMENTS.md](docs/REQUIREMENTS.md) §13 を参照。

- **サーバーの公開範囲** — 各自のPC・スマホから使うには到達経路が要る。同一LANなら管理者PCのIPで足りるが、自宅からも使うならVPN（Tailscale等）やCloudflare Tunnelの選定が必要
- **合言葉が漏れたとき** — `DEBATE_APP_PASSWORD` を変えれば全員のログインが無効になる
- **本番大会で使う場合** — 改めて大会要項でAI利用の可否を確認すること（練習・模擬戦では確認済み）
- **引用文献の再配布範囲** — 事例DBでの教材公開は、ゼミ内の引用とは範囲が異なる
